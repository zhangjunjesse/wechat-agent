# 飞书文档读写 SOP（ADR-0021）

通过 `lark_*` 工具完成所有飞书文档操作。**前提**：用户必须先授权自己的飞书
（`lark_auth` 返回链接，用户打开授权后 token 存服务器，per-user 隔离）。

## 执行流程

### 1. 确认授权状态

先调 `lark_auth_status`：
- 未授权 → 调 `lark_auth` 拿授权链接发给用户，等用户授权后再继续（不要在没有 token 时硬调读/写）；
- 已授权（或授权过期 → 让用户重新授权）→ 继续。

### 2. 定位文档

| 用户给了什么 | 怎么定位 |
|---|---|
| 文档链接（`https://xxx.feishu.cn/docx/xxx`） | 直接用（lark_read_doc 支持链接） |
| 只说了主题（"我上次写的关于 AI 的方案"） | `lark_search_docs` 按关键词搜，把结果列给用户确认是哪篇 |
| 只要新建 | 直接 `lark_create_doc`（先确认标题和内容） |

### 3. 读文档

- `lark_read_doc` 返回 markdown 正文；内容过长会截断并提示，用户要看更多时按段续读
  （可让用户给文档链接换一种方式，或提示内容截断位置再读）。
- 读完不要急着总结——用户要什么就给什么；需要提炼时基于读到的内容回答。

### 4. 写文档（必须确认）

**写操作三连**（产品约定，不可省略）：

1. 调 `ask_user`，向用户**复述将要做的改动**：
   - 创建：`将新建文档「标题」，内容概要：…`
   - 编辑：`将向文档 <标题/链接> 追加以下内容：…`
2. 用户确认 → 调 `lark_create_doc` / `lark_edit_doc` 执行；
3. 用户拒绝/有修改 → 按用户意见调整后再确认，**绝不能未经确认就写入**。

## 常见问题

- **"尚未授权飞书"**：引导 `lark_auth`，把授权链接发给用户，授权完成后再操作。
- **"授权已过期"**：refresh token 过期（30 天未用），让用户重新授权一次。
- **"飞书 API 错误 / permission"**：转述错误；如需额外权限，可提示管理员在飞书开放
  平台后台为该应用补充 scope。
- **文档是旧版 doc 或表格（bitable）**：当前能力只覆盖云文档（docx）；旧 doc/表格
  如实告知暂不支持，不要编造操作结果。
