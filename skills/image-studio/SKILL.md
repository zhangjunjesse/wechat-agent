# 图片处理 SOP（生成 / 编辑 / 重绘）

通过 `image_generate` 工具完成所有图片处理。三种模式：

| 模式 | 适用场景 | 原图保留度 |
|---|---|---|
| `generate`（默认） | 文生图 / 图生图（参考图仅作风格参考，重新生成版式） | 低 |
| `edit` | 在原图基础上改细节（加按钮、换文案、调颜色），保留主体结构 | 高 |
| `inpaint` | 只改某一局部区域，其余全部原样 | 极高 |

## 执行流程

### 1. 理解用户意图，选对模式

- "生成一张……的图" / "画一个……" → `generate`（文生图）
- "照着这张图/这个风格来一张……" → `generate` + `image`（图生图，风格参考）
- "在这张图上把……改成……" / "给这个截图加个……" → `edit` + `image`（编辑，保留主体）
- "只把这块区域改成……，其他地方别动" → `inpaint` + `image` + `mask`（局部重绘）

### 2. 确认图片来源

- 用户发来的图片附件：在 `inbox/` 目录（路径形如 `inbox/<时间戳>-<文件名>`），先用 read_file / list_files 确认实际路径
- 已有文件：直接用相对路径
- 没有参考图 → generate 模式，无需 image

### 3. 调用 image_generate

- `prompt` 必填，要具体：主体、风格、构图、要改的元素。edit/inpaint 时明确"其余保持不变"
- 编辑/重绘的原图必须存在：先读文件确认，不要凭空引用路径
- inpaint 的 mask 图：PNG 格式、含 alpha 通道、透明区域（alpha=0）= 待重绘区、尺寸须与原图一致。mask 来自：① 用户提供的 mask 附件；② 没有时如实告诉用户"需要一张把待改区域涂成透明的 PNG mask 图"，请用户提供或说明限制，不要编造
- `size`/`resolution` 默认 1:1 / 1k，用户有明确比例要求时传（如 16:9 海报）

### 4. 交付结果（必须）

- 工具返回 `images/xxx.png` 路径后，**必须调用 `send_file` 把图片作为真实消息发给用户**（微信对话）；网页对话改用 write_file 的下载链接机制
- 不要说"图片已生成"却没有任何交付动作

## 常见问题

- **工具提示未配置 API Key**：如实转述，提示联系管理员配置，不要反复重试。
- **上传失败（>10MB / 格式不支持）**：图片只支持 jpg/png/webp/gif 且单张 ≤10MB，如实告知用户限制。
- **任务失败或超时**：转述工具返回的具体错误（生成失败原因/超时），必要时降低分辨率（1k）重试一次，不要编造成果。
- **用户想要特定尺寸/分辨率**：从 `16:9`、`2:1`（海报）、`9:16`（手机竖屏）、`2k/4k`（高清）等常见组合里选，超范围先问用户。
