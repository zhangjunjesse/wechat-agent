# 后台任务委派 SOP（DESIGN-task-delegation.md / ADR-0024）

把耗时任务派给后台子 agent，主对话**立刻回复**、不阻塞；子任务完成后系统自动通知用户。
目标：用户永远不用盯着屏幕等，也不会怀疑"是不是挂了"。

## 1. 四条判据——全过才派

对用户的要求逐条自问，**四条全"是"才调 `delegate_task`**：

| # | 判据 | 说明 |
|---|---|---|
| 1 | **自包含？** | 不需要再问用户任何信息就能做完（子 agent 看不到你们的对话） |
| 2 | **多步？** | 预计 ≥3 次工具调用，或需要等外部接口（导出/下载/抓多篇正文/生成图片） |
| 3 | **够长？** | 预计 ≥30 秒（更快的话自己做，派发本身有开销） |
| 4 | **不依赖对话？** | 若依赖对话上下文，先把必要信息写进 `context` 再派（不要整段对话） |

## 2. 明确不该派（做错反而不如自己做）

- 简单问答、单次查询（"现在几点""这个群叫什么"）→ **直接答**；
- 需要与用户澄清或多轮确认（"帮我改一下那个方案"——改哪份？改成什么？）→ **先问清**；
- 用户催"马上/立刻"且任务本身很快 → 直接做；
- 敏感操作（删除、发消息给别人、改动线上数据）→ 逐步确认，不要交给后台；
- 同一目标已经在处理中 → 先 `list_tasks` 看看，不要重复派。

## 3. goal 怎么写（决定成败）

子 agent 只看到 `goal` + `context`，写不清它就会猜。模板：

```
背景：<为什么做这件事，一两句>
目标：<要做出什么，可验证>
交付：<什么形式——文件（什么格式/命名）/ 一段总结 / 图片；发给谁>
成功标准：<怎样算做完>
边界：<不许做什么、信息不足时怎么办（明确说缺什么，不要编）>
```

`context` 只放**必需素材**：文档链接、用户偏好、上次相关结论——不要贴整段对话。

## 4. 派发与完成时怎么说

**派发后立刻回一句**（不要等）：
> ✅ 已派发任务 #3（导出《季度总结》为 PDF），完成后我把文件发你。

**绝对不要**：编造任务结果、说"正在处理中我看看"然后把用户晾着、反复 `task_status` 轮询（任务完成会自动通知）。

**完成通知由系统发出**（含任务 id 与结果摘要）；用户如果说「重试 #3」，调 `retry_task`；
问「我派的任务怎么样了」，调 `list_tasks`；问某个任务详情，调 `task_status`。

## 5. 什么时候也不该用工具，只回一句话

- 用户只是问能力（"你能导出飞书文档吗？"）→ 直接答，**不要真去派任务**；
- 用户没说清要做什么 → 先问一句，别猜着派。

## 6. 校准（用户反馈要记住）

用户说「这个不用派，直接做」或「这种以后都派出去」→ 把它记成用户偏好（调用记忆里的
偏好记录能力），后续同类任务按该偏好判断。
