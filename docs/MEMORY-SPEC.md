# 用户记忆系统设计规格

> 本文件是微信个人助手「记忆系统」的完整设计规格，作为实现与验收的唯一权威来源。
> 状态：已定稿，待分阶段实现。

## 一、记忆能力目标（8 项）

1. **个人信息保留**：记住用户身份等长期个人信息。
2. **偏好追踪**：跟踪并记住用户的长期偏好。
3. **上下文切换**：在多个话题之间切换时保持连贯。
4. **记忆更新**：当用户提供与旧信息矛盾的新信息时能正确处理。
5. **多会话连续性**：跨会话保持知识。
6. **复杂思考**：基于多个记忆片段联合思考。例：用户对花生过敏时，推荐泰国菜应主动提醒注意花生成分。
7. **时间感知**：记住日期、理解相对时间、进行时间计算。
8. **冲突解决**：识别并处理记忆之间的不一致。

## 二、三层评估框架

### 第一层：基础回忆
Agent 能存储和检索用户直接提供的、结构化的、无歧义的信息。如「我的会员号是 12345」，在需要时精准返回。

### 第二层：多会话检索
Agent 在面对多个不同时期的会话时，能检索出相关信息并推理判断。例：用户先后提到他有两辆车，后续问「为我的车预约保养」时，系统需找出全部车辆信息并主动询问需要为哪辆服务，而不是随便猜一辆。

### 第三层：主动服务
Agent 能跨越很久之前的会话信息，提供有预见性的帮助，从看似无关的记忆中发现深层联系。例：预定国际航班时主动关联数月前的护照信息，发现即将过期并发出预警。

## 三、记忆存储方式

采用 **Advanced JSON Cards** 方式，从信息存储走向知识管理。

每个卡片不仅记录事实，还加入：
- 信息来源的叙事背景；
- 主体身份；
- 与用户的关系；
- 时间戳。

设计思想：同一条信息在不同场景下可能有不同含义——「张医生」可能是用户自己的牙科医生，也可能是用户父亲的心脏病医生，脱离了具体情境就无法理解。

## 四、记忆的类型

1. **情境记忆（Episodic）**：关于具体事件和经过的记忆；记录一个具体事件的时间、对象和细节。
2. **语义记忆（Semantic）**：从具体事件中抽象出来的一般性知识；从多次对话中提炼出的稳定特征。
3. **程序记忆（Procedural）**：关于行为模式和流程的记忆（类比人类骑自行车的能力）。
4. **工作记忆（Working）**：除上述三类长期记忆之外，对应 Agent 上下文窗口，用于处理当前任务的临时信息空间。与长期记忆动态交互——重要信息选择性转移到长期记忆，相关长期记忆被激活加载到工作记忆。

## 五、记忆压缩与整理机制

### 第一层：重要性评分筛选
综合 4 个因素：
- 访问频率（记忆经常被检索）；
- 时间衰减（越久远越容易被遗忘）；
- 情感强度（带有强烈情感标记的记忆更易保留）；
- 信息独特性（重复信息的重要性降低）。

低于阈值的记忆标记为可压缩或可删除。

### 第二层：聚类压缩
相似记忆被分组，每组生成代表性摘要；原始详细记忆可存档到二级存储。

### 第三层：抽象和泛化
从具体情境记忆中提取一般性规律，转化为语义或程序性记忆。

## 六、实现约定

- 记忆以 JSON Card 结构存储（含事实、情境背景、主体身份、关系、时间戳）；
- 与现有 `SessionStore`（SQLite，transcript + summary）分层：长期记忆独立于会话 transcript；
- 记忆读写均按 `user_id` 隔离；
- 记忆更新与冲突解决遵循「新信息可覆盖旧信息，但要保留可审计的时间戳」。
