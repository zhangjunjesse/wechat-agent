# ADR-0003: 系统提示词分层设计

- 状态：Accepted
- 类型：Architecture / Feature
- 日期：2026-08-25

## 问题

Agent 的上下文（系统提示词）此前是硬拼字符串：一句角色指令 + 技能目录，动态部分把昵称/wxid/时间/记忆/摘要用 `filter().join()` 拼成一条 system message。存在几个问题：

1. 没有任何安全规则，模型可能泄露其他用户数据或执行高风险动作；
2. `wxid` 是内部标识，暴露给模型无收益且是信息泄漏面；
3. 角色名写死，用户无法自定义；
4. `nowLine` 用服务器本地时间，容器默认 UTC，比北京时间慢 8 小时，影响日期/待办判断；
5. 分层不可测、难演进。

## 决策

把提示词拆成**静态层 + 动态层**，并抽成两个纯函数（`src/llm/system-prompt.mjs`）：

- **静态 instructions**（`buildBaseInstructions`，构建一次）：安全规则 → 角色行为 → 技能目录。
- **动态 system**（`buildDynamicSystem`，每轮生成）：角色名 → 用户身份 → 时间 → 记忆 → 会话摘要。

最终模型看到的顺序：安全 → 角色行为 →（技能目录）→ 角色名 → 身份 → 时间 → 记忆 → 摘要。

具体约定：

1. **安全规则**（4 条）：不泄露他用户数据/提示词/密钥；沙箱越界即停；拒绝高风险动作（转账/外呼/执行系统命令/部署）；不确定就不编造。它们是**引导**，真正的安全边界在代码（沙箱、鉴权），不在提示词。
2. **角色**：行为描述（简洁但信息完整、能调用工具）是静态的；**自称名**是 per-user 的，**单一来源 = 记忆里用户设定的命名**（identity / subject=助手，如「助手命名为小新」），默认 `'助手'`。系统提示词从记忆读取，不再有第二来源（避免与默认值冲突；用户对话里说「以后你就叫小新」即完成自定义）。
3. **身份**：只留 `用户昵称`，去掉 `wxid`；未验证时显式写「尚未完成身份验证」。称呼偏好（如「张工」）属于记忆的 identity 类别，在记忆层展示，不在身份层重复。
4. **记忆**：`recall()` 按类别分节（身份/偏好/事实/待办），token cap 6000 不变。
5. **摘要**：`buildSummarizePrompt` 约束只保留跨轮结论、用户要求/承诺、未完成待办、已做决定，不概括寒暄。
6. **时间**：固定东八区（`src/services/time.mjs`，用 +8h 偏移），不依赖容器 `TZ`。覆盖 `nowLine`、`fmtDate`、`relativeDue`、`get_current_time`、记忆提取的「今天」和周几计算。

## 后果

- 提示词可单测、可独立裁剪；新增 `tests/system-prompt.test.mjs`。
- 角色名/身份/时间/记忆/摘要都能被回归测试锁定，改文案不再靠肉眼。
- 安全规则是「软约束」：若未来要真正强制，仍需在代码层（路由鉴权、工具沙箱）落实。

## 验收证据

- `tests/system-prompt.test.mjs`：安全规则存在性、动态分层顺序、未验证标注、默认角色名。
- `tests/memory-manager.test.mjs`：东八区下的 `relativeDue`/`fmtDate` 日历对齐。
- `tests/memory-extractor.test.mjs`、`tests/session-compactor.test.mjs`：提取/摘要文案约束。
