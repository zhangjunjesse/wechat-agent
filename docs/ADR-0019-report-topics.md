# ADR-0019: 日报主题订阅——per-user 个性化生成，严格隔离

- 状态：Accepted（**§2 的"多主题合并进一次生成"被 ADR-0027 取代**：per-user
  隔离本身不变，但用户的多个主题不再合并成一份，改为每个主题独立生成/去重/
  推送一份；见下方 §2 末尾的更新说明）
- 类型：Architecture / Feature
- 日期：2026-09-15
- 关联：ADR-0017（日报管道）、ADR-0018（图文一体海报，本记录在生成环节引入个性化维度）、
  ADR-0014（定时任务）、**ADR-0027（同一用户的多主题从合并改为独立成篇）**
- 前身：ADR-0017「内容一次生成 + 扇出（放弃逐用户个性化）」条款——本记录为其 v2 落地

## 问题

公共任务「每日早报」此前所有订阅者收到**同一份公共版内容**（ADR-0017 明确放弃
个性化）。用户希望：订阅自己感兴趣的话题（如 AI、芯片、新能源），日报围绕这些
主题生成；并且**主题订阅是每个用户自己的，严格隔离，不串他人**。同时需要产品侧
**主动引导**用户完成「定时任务 + 主题」订阅。

## 决策

### 1. 数据模型：per-user 主题（`TaskStore.report_topics` 表）

- `report_topics(user_id, task_name, topics JSON, updated_at)`，主键 `(user_id, task_name)`。
- API：`setReportTopics`（替代式设置；空数组 = 清除个性化回到公共版；**未订阅先拒绝**）、
  `getReportTopics`、`reportTopicsByTask`（调度器分组用，只返回设了主题的用户）、
  `listReportTopics`。所有键按 `user_id` 隔离。

### 2. 生成模型：公共版 + 每用户个性化版（`TaskScheduler.#runReportTask`）

- 按 `reportTopicsByTask(task.name)` 把订阅者分为：**无主题组**（共享公共版，一次生成
  不随人数翻倍）与**有主题组**（每个用户单独生成，prompt 注入其主题：`buildReportPrompt
  (task, recent, { topics })` → "用户订阅的个性化主题：…，请优先挑选这些主题相关新闻"）。
- 报告按用户维度入库：`ReportStore.reports` 新增 `user_id` 列（迁移兜底）；报告 id =
  `reportIdOf(taskId, runAt, userId)`（有 userId 时 hash 含用户维度，**与公共版 id 不同、
  互不覆盖**；公共版 hash 保持原样，公网链接延续）。
- **去重窗口按用户维度隔离**：`recentFingerprints/recentTitles` 加 `{ userId }` 过滤，
  个性化版只与本人历史比对，不混公共版、不串他人。
- 海报/推送/公网页/追问机制沿用（ADR-0018）；个性化报告海报标题显示主题徽标
  （如「AI · 芯片」替代默认 tag）。

  > ⚠️ **本条已被 ADR-0027 取代（2026-09-16）**：把一个用户的多个主题合并进
  > **一次** `buildReportPrompt(task, recent, { topics })` 调用、由模型自行权衡
  > 各主题的名额分配——这导致"订阅了 2 个主题但每天还是只收到 1 条推送"的
  > 落差，且没有保底名额，某个主题当天可能被挤到 0 条而不自知。ADR-0027 改为
  > **每个主题各自独立调用一次**（各自 prompt、各自去重窗口、各自海报、各自
  > 推送），海报标题的"主题徽标"相应从多主题拼接（「AI · 芯片」）变成单主题
  > （每份海报只显示自己那一个主题）。id/去重按 `{userId, topic}` 双维度隔离，
  > 取代本条的纯 `{userId}` 单维度。

### 3. 工具与引导（agent 对话即完成订阅）

- 新工具 `update_report_topics { name, topics[] }`：用户说「订阅 AI 主题」「关注 芯片
  新能源」「换个主题」时调用（设置/清除；未订阅拒绝并提示先订阅）。
- 新工具 `list_report_topics`：查看自己的主题订阅。
- **引导入口**（主动、友好）：
  - `subscribe_task` 成功后追加提示"告诉我感兴趣的主题（如『订阅 AI 主题』），日报会更贴合你"；
  - 海报底部引导行：公共版"想定制感兴趣的主题？回复『订阅 AI 主题』"；个性化版
    "当前主题：… · 想调整？回复『订阅 新主题』"；
  - 推送短描述含"想定制感兴趣的主题？回复『订阅 AI 主题』即可"。
- `get_daily_report` 优先返回自己的个性化报告，无则回退公共版。

## 备选（不选的理由）

- **保持"一次生成 + 扇出"，只在展示层差异化**：内容相同则"主题订阅"无意义，用户
  要的是内容贴合。
- **按主题分组共享生成**：主题组合多、分组收益低，先做每用户独立（量小），量大再加
  分组缓存。
- **主题存 profile（JSON）**：多租户并发写 JSON 有覆盖风险，独立 SQLite 表更稳（与
  tasks.db 同库，事务一致）。

## 后果

- 每个设了主题的订阅者每天**多一次** agent 生成（成本随有主题用户数线性）；无主题用户
  不受影响（仍共享公共版）。
- 主题是用户自己的：u1 设 AI、u2 设机器人，各自收到各自主题的日报、各自独立去重，
  **互不串**（测试断言覆盖）。
- 未订阅先拒绝设主题；清除主题回到公共版，无数据残留负担。

## 验收证据

- `npm test`：**278/278 全绿**。新增用例：
  - task-store：report_topics CRUD + 未订阅拒绝 + **u1/u2 主题互不可见**；
  - report-store：user-scoped 报告与公共版 id 不同、去重窗口按维度隔离；
  - task-scheduler：u1(AI)/u2(机器人)/u3(无) → agent 恰好 3 次（公共版 1 + 个性化 2）、
    prompt 主题隔离（u1 只见 AI、u2 只见机器人、公共版无主题行）、3 份不同 id 报告
    （各自标题 AI头条/机器人头条/公共头条）、推送 URL 互不相同（不串）；
  - task-tools：update/list 主题工具 + 未订阅拒绝 + get_daily_report 优先个性化。

## 遗留（诚实边界）

- 有主题用户数增大后的成本优化（按主题分组/缓存）未做，量大了再评估。
- 主题粒度：目前是自由文本（如"AI"），未做同义词归一（"AI" vs "人工智能"算两个主题）；
  生成靠模型理解，够用，后续可按反馈加归一。
- 引导文案在海报/短描述/订阅回执三处，后续可按实际转化率调整话术。
